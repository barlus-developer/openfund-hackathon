# Limitations and external requirements

This is a working **development/testnet demo** system with local Anvil and remote RPC configuration, not a production payment service, audited protocol or regulated stablecoin. No real funds were used. OFL's 1:1 LAK reference is not enforced by code. Development tokens have no fiat backing or redemption. Reserve custody, mint/redeem operations, reserve attestations/reconciliation, compliance and legal review remain external work. No off-chain payment backend is included.

The immutable issuer can increase supply without reserves. Its registration handshake is a guard against accidental recipient protection, not a proof of trusted code. A malicious issuer can register a mimic. A compatible zero-balance donor/recipient contract registered later can have incoming raw refunds/payouts blocked; the tested failed transfer preserves its entitlement but registration cannot be undone. EOAs cannot be registered. It cannot move existing treasury assets. Protecting an address is irreversible.

No independent audit, formal proof, public deployment or public explorer verification was performed. Remote RPC/import and IPFS request protocols are tested, but a live user-service deployment/upload still requires the actual endpoint and signer/upload capability. Immutability prevents emergency patches to deployed contracts. No recovery exists if approvers lose enough keys. Collusion and misleading charitable claims are possible. Official protocol membership is not identity verification.

The current interface uses Lao interaction labels and donor policy disclosures. English preferences retained from earlier versions do not switch the interface. Some technical identifiers and development guidance remain in English. Translation quality, accessibility with assistive devices, real MetaMask extension prompts and physical mobile devices require further human review. Automated wallet tests use a separate development-only provider harness, not an extension.

RPC availability, provider log limits, rate limits and chain reorganizations affect the browser. Discovery is best-effort over loaded windows, not an instant exhaustive index. Large datasets need repeated window loading and current-state checks. Wallet dashboards and proposal lists intentionally limit rendered tasks; loaded-range notices disclose this. Public RPC pricing/access is deployment-specific. Mobile requires a reachable RPC; a phone cannot use a computer's localhost.

IPFS uploads use a user-controlled HTTPS Kubo endpoint (or loopback node), or Pinata public IPFS through a temporary signed upload URL. User node authentication stays in memory; Pinata JWTs stay in the one-shot CLI. Endpoint availability, narrow CORS and actual pinning/service credentials are external requirements. CID references can be entered without an account. No pinning secrets are bundled. The app verifies up to 5 MB of gateway bytes with keccak256 when requested, but cannot guarantee persistence, privacy or truth. Unavailable or mismatched documents remain visibly unverified. No sensitive beneficiary documents should be published.

Gas uses the configured network’s native currency even when OFL is donated/refunded. Pending payout proposals reserve no funds and may become underfunded. Token/native assets arriving outside the supported OFL donation path are uncredited and may be permanently stuck; there is no administrator rescue.

The checked-in local manifest is evidence of an actual session deployment, not a portable persistent chain. A fresh Anvil must be redeployed and the manifest regenerated. Snapshot-based verification restores the seed state; test-run hashes are not retained as canonical history afterward.
